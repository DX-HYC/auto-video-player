一个通用的浏览器扩展：自动识别网页里正在播放的视频和播放列表，视频暂停时自动续播，播放结束后自动点击下一个视频。

## 支持的平台

扩展会按**域名自动判定当前平台**，并只启用该平台的一套策略。各平台可单独启停（见下方「使用」）。

| 平台 | 域名 | 处理方式 | 状态 |
| --- | --- | --- | --- |
| 网梯科技 | `webtrn.cn` | `.s_point[itemtype="video"]` 目录识别 · `completestate` 完成判定 | **已冻结** |
| 江西师范大学 | `jxnu.edu.cn` | 百家云播放器接管（无 `<video>`）· 目录百分比进度 | 维护中 |
| 通用兜底 | 其余站点 | `<video>` 元素基础连播能力 | 维护中 |

> **为什么按平台隔离**：不同平台的目录结构与完成标记完全不同，早期把各平台的特判都写在
> 同一条共享路径上，改动一个平台存在波及另一个的风险。现在每个平台的专属逻辑都受
> `profileAllows(id)` 准入保护——在 A 平台上，B 平台的判定分支根本不会执行。
>
> 「已冻结」表示该平台的逻辑不再随其他平台的开发而改动，任何变更必须先让
> `tests/selftest_whaty_frozen.js` 全绿。

## 功能

- **平台自动识别**：打开页面即按域名判定平台，面板上会显示当前平台名。
- **自动识别视频**：扫描页面中所有 `<video>` 元素，并监听动态加载的新视频（含 iframe 内嵌播放器、Shadow DOM）。
- **自定义播放器接管**：播放器不在 `<video>` 里（canvas + WebAudio，如百家云）时，直接从播放器控制条读取进度并模拟起播。
- **暂停自动续播**：检测到视频被暂停（非播放结束）时，自动恢复播放。
- **识别待播列表**：用启发式算法解析课程/播放列表，区分 **已播 / 播放中 / 待播** 状态；自动穿透 iframe，识别主页面和子页面中的目录。
- **自动连播**：当前视频播放结束后，优先点击平台自带的"下一集"按钮；没有时按目录顺序点下一个待播项，遇到未展开目录会自动展开父级后再点击。
- **倍速播放**：可选开关，支持 1.0x ~ 5.0x 多档倍速，视频切换后自动保持，关闭即恢复 1 倍速。
- **读取视频进度条**：实时显示当前视频播放进度（`00:33 / 34:06`）和课程总进度百分比。
- **悬浮面板**：页面右下角实时显示运行状态、视频数量、目录统计，可拖拽、可折叠，支持手动"立即播放下一集"，可展开调试日志查看识别过程。

## 安装步骤

1. 打开 Chrome 或 Edge，地址栏输入 `chrome://extensions`（Edge 为 `edge://extensions`）。
2. 打开右上角 **「开发者模式」** 开关。
3. 点击 **「加载已解压的扩展程序」**。
4. 选择本文件夹（`auto-video-player`，包含 `manifest.json` 的那一层）。
5. 打开任意视频网站（B站、YouTube、课程网站等），页面右下角会出现悬浮面板即表示已生效。

## 使用

- 面板 / 扩展图标弹窗里可开关：**平台启停**、**总开关**、**进入页面自动起播**、**暂停自动续播**、**播完自动下一集**、**倍速播放**。
- **平台启停**：可单独关闭某个平台。关闭后，该平台所属域名上扩展完全不动（不建面板、不扫描、不接管），适合在其中某个平台出问题时先隔离该平台、不影响其他平台。重新勾选即可恢复，无需刷新页面。
- 设置通过 Chrome 同步存储，改动会实时生效到已打开的页面。
- 若不希望某些页面自动运行，可在扩展详情里通过「网站访问权限」限制。
- **只在有播放内容的页面工作**：打开白名单内的普通页面（首页、列表页等没有任何视频/播放器特征的网页）时，扩展不会弹出面板、不做任何扫描；页面后续真的出现播放内容才会自动启动。

## 商业授权（作者必读）

本插件采用**离线授权码**机制：没有有效授权时，插件在网页上完全不工作（不扫描、不起播、不自动下一集），只在页面右下角显示「🔒 插件未授权」卡片，需联系作者获取授权码。

授权为**程序级授权**（v2.1.1 起）：不绑定域名、不绑定平台——授权码只证明"该用户有权使用本程序"，激活后**全部功能、全部已支持网站**均可使用。

**用户激活（两种方式任选）：**
1. 打开任意已支持的学习网站，页面右下角「🔒 插件未授权」卡片里粘贴授权码 → 点「激活」；
2. 点浏览器工具栏扩展图标，在弹窗顶部的授权卡里输入激活。

授权码保存在 `chrome.storage.sync`，随 Chrome/Edge 账号同步，换电脑登录同一账号无需再次激活。

## 更新日志

### v2.1.2（2026-10-27）全栈体检：5 个 bug 修复 + 性能优化

对全部源码（manifest / background / content / popup / license / shadow_bridge，约 4900 行）做了一次完整通读，修复确认的问题：

- **修复 `readCustomPlayer()` 调用未定义的 `pick()`**：「时长读不到」分支一进去就抛 ReferenceError 被静默吞掉，自定义播放器会被永远当成"暂停中"（现有测试都走"时长读得到"分支，从未覆盖）。
- **修复 SPA 路由监听重复注册**：待命再唤醒会叠加 popstate/hashchange 监听、反复包装 `pushState`、`1500ms` 轮询 interval 越积越多（且不在 tickTimers 里，待命时清不掉）；改为监听器只装一次 + 轮询纳入 tickTimers 统一管理。
- **修复 background 标签页注册竞态**：`addTab/removeTab` 原是"异步读 storage → 改 → 写回"，两个标签页几乎同时注册时后写覆盖先写（丢更新），被丢的标签页收不到看门狗唤醒；改为内存数组为单一事实源 + 启动时恢复一次（单 Promise 去重）。
- **修复 Shadow 桥升级不刷新 matches**：扩展升级后域名清单变了，已注册的 MAIN world 桥不会更新，新域名永远注入不了；改为注册前逐项比对，过期则 `updateContentScripts`（老内核自动降级为"注销 → 重注册"）。
- **修复面板"空壳 video"统计错误**：改用 `isRealVideoObj` 直接统计，避免页面存在重复 src 的 video 时虚报空壳数量。
- **健壮性**：`chrome.tabs.sendMessage` 同时兼容 callback 与 Promise 两种 API 形态；起播复查定时器（3s/8s/16s）重新调度前先作废旧句柄；ping 向孙辈 iframe 转发；倍速下拉存储值不在选项内时动态补选项，`updateUI` 对面板控件逐个空值保护。
- **性能**：video 元素清单与目录容器查找加 TTL 缓存，大页面 CPU 占用显著下降。
- **测试**：新增 `tests/selftest_robust.js`（44 项），全量回归 **184/184** 通过。

### v1.8.1
- **修复「浏览器最小化 / 切到后台后不自动播放、不自动跳转」**（后台定时器节流导致）：
  - **根因**：Chrome 对后台标签页实施定时器节流（隐藏一段时间后 `setInterval` 被压缩到每分钟一次）。而 `pickBestFrameForNext` / `pickBestList` 用 12 秒有效期过滤 `frameStates`，另有 15 秒清理定时器直接 `delete frameStates[k]` —— 后台时帧状态被判为过期或删除，`pickBestFrameForNext()` 返回 `null`，日志打出「未找到有效目录帧」，于是跳不动；回到前台定时器恢复，积压任务一起执行，表现为"打开浏览器才继续"。
  - **时效判定按可见性放宽**：新增 `frameStateMaxAge()`，页面不可见时有效期从 15 秒放宽到 5 分钟（目录结构不会因后台而改变），前台保持严格；清理定时器同步放宽。
  - **调度改用消息驱动**：`ended` 到达时先 `analyzeAndReport()` + `broadcastDown(ping)` 实时拉起子帧上报（`postMessage` 投递不受定时器节流影响），并抽出统一入口 `dispatchNext()`；选不到目录帧时安排一次重试。
  - **新增后台看门狗**：新增 `background.js`（Service Worker）+ `chrome.alarms`，每分钟唤醒一次并向已注册标签页发消息，内容是 `scanVideos → analyzeAndReport → ensurePlaying → 必要时补跳下一集`。消息投递会立即执行页面脚本，不受节流限制。无需 `tabs` 权限，仅用已有的 `storage` 加 `alarms`。
  - **被动暂停自动恢复**：区分"用户主动暂停"与"后台被动暂停"。页面不可见时发生的暂停（浏览器节流或平台防挂机检测）会自动恢复播放，用户在前台的主动暂停不受影响。
  - **保证下一集真的起播**：新增 `ensurePlaying()`，视频刚开始播放（`currentTime < 15`）却处于暂停时自动尝试启动（优先模拟点击播放按钮，`play()` 兜底），避免跳过去之后卡住不动。
  - **恢复可见即时补齐**：`visibilitychange` 回到前台时立即刷新并检查是否有遗漏的跳转。

## 说明与限制

- "识别列表"采用通用启发式策略，大多数主流视频网站都能命中；极少数结构特殊的网站可能需要针对该站做适配。
- 自动续播依赖页面已发生过用户交互（浏览器自动播放策略），正常浏览观看场景下均满足。
- 本工具仅用于个人学习、课程连播等合法场景，请遵守目标网站的条款。
